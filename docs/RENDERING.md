# 悬浮歌词渲染层

歌词 HUD 的绘制、排版、动画与交互。核心代码在 `common/src/main/java/com/linklyric/`，平台相关副本在 `fabric` / `neoforge` 的 `render` 包。

返回 [README](../README.md)。

## 链路

```
Salt Player ──(spmod 插件)──► 127.0.0.1:35400 ──► BridgePlaybackSource
                                                        │
                                          FloatingLyricRenderer ──► HUD
```

HTTP 桥接严格要求 v2：`v: 2`、`type: "snapshot"`，以及 `track` 内的 `title` / `artist` / `durationMs`、顶层 `positionMs` / `playing` / `seq`。未知版本或缺失必需字段按请求失败处理，不降级为整行显示。JSON 深度上限 64，整数字段精确读取有符号 64 位整数，不接受小数、指数或字符串数字。完整字段与 ETag 省略条件见 [协议文档](PROTOCOL.md)。

## 显示能力

支持 1–10 行显示，提供横排堆叠、弧形、环形三种排布，以及默认关闭的长句折行。弧形与环形不滚动，折行最多 4 段，超出截断并加省略号。默认横排、底部居中，纵向锚点与左右留白可配置。

这些排布能力不等于已实现灵动岛、侧边栏或物品栏等产品样式。

## 排版

**多行堆叠。** 默认横排支持多行堆叠，不是固定双行；另有弧形与环形排布。行数可调 1–10，`LineLayout` 把「当前行 + 后续若干行」当作一整块，块心固定在锚点上，逐行往下排。主行基线因此不随「有没有下一句」跳一行高。

**所有样式对所有行生效。** 副行与后续行共用对齐、字重、阴影、字号缩放，只有字号按 `SUB_TEXT_FONT_SCALE` 收一档。

**副行左边界按缩放后宽度算。** `drawTextScaled` 以 `(x, y)` 为原点缩放，文字实际占据 `[x, x + width*scale]`。用未缩放宽度居中会让副行中心偏左 `(width - width*0.8)/2` 像素，行数越多越明显。

**字号**靠 `Pose2D` 变换栈实时缩放整块歌词，锚点是歌词块中心，调字号时位置不漂。缩放必须作用于绘制，只参与宽度计算而不改字形时滑条拖动会毫无变化。

**对齐**把行宽换算成左边界。左右对齐以可用区间两端为锚，不用「中心减半宽」重算。视口、主行、副行三处使用同一套换算。

**未唱内容用透明度表达**，不换灰色。灰色是第二种颜色，会与用户选定的已唱色冲突；透明度只减弱同一颜色的存在感。非主行统一用 `UNSUNG_ALPHA`（`0.38`）。

**整体不透明度**作用于所有行（主行、后续行、间奏），在渲染入口统一相乘。分散到各条绘制路径会漏掉某一条。下限取 10%，不取 0。

**间奏提示**可配三档：空白、`···`、`间奏`。空白档不出画，但仍重置行状态。

**裁剪高度**取 `painter.lineHeight() + LIFT_HEADROOM + SHADOW_HEADROOM`，由平台层报告真实行高。用常量 `LINE_HEIGHT` 算出固定 16 像素会让 fallback 字体提供的更高中文字形把阴影沉到框外。

**笔画加粗使用 SDF 距离场。** `LyricStyleConfig.weightPercent` 提供 0–100 的界面刻度，通过距离场阈值偏移加粗笔画，字距不变，不使用错位副本叠画或原版 `§l` 模拟。`Weight` 枚举只保留 `REGULAR`。描边、描边宽度与颜色、柔和阴影分别配置。

## 逐字染色

**进度派生。** 逐字上浮由染色进度派生：字被染到多少就升起多少，完全染完时正好升到顶点。两者共用同一个进度量，没有独立的时间常数。

**两条曲线。** 共用进度量不等于共用曲线：

| 项 | 曲线 | 理由 |
|---|---|---|
| 染色前沿 | 线性，只做一次 `smoothstep` 收边 | 问的是「唱到哪了」，属于事实，必须与音频时间严格成正比 |
| 上浮位移 | `CubicBezier(0.25, 0, 0.2, 1)` | 问的是「起来得好不好看」，属于观感，只需重新分配速度分布 |

上浮曲线不改变起止时刻与总量，两者仍在同一时刻开始与结束。

**不短路。** 上浮不做「整行唱完就全部置满」的短路。已唱宽度是累加值，行级数据与逐字混合时可能宽度先到而行级内进度未走完，短路会盖掉字级差异。

**抬升保持浮点。** 抬升量只有约 0.9px，绘制前取整会让曲线只剩 0 与 1 两档。逐顶点写入接浮点坐标，位移因此连续。

**字级上浮按字号比例。** 幅度是 `字号 × 0.10`，保持浮点。裁剪预留空间必须由同一个幅度算出，否则抬起的字顶部会被削平。

**行级歌词按行内比例插值。** 宿主并非总提供逐字时间：没有逐字数据的歌，`lyricsCells` 只有 1 个元素。按行内时间比例做线性推进，观感接近卡拉OK，且不伪造不存在的字级时间。

**两层真实颜色。** 整行先以未唱色铺满，再把已唱段用已唱色重画一遍。两层共用同一个 `textX` 与同一份抬升表，只有裁剪区不同，像素严格重合。两层不得各自位移，否则两种颜色会在中途对穿形成重影。「整行未唱色 + 已唱段重画」的路径保留，供不支持逐顶点染色的平台降级使用。

**过渡带用 RGB 插值。** 唱到某字时交界处用 `ColorMath.lerp` 直接插值「已唱色 → 未唱色」，每段取中间色并以不透明 alpha 绘制。插值对象是颜色本身，与背景无关。

### 四个状态坑

**歌词指纹不能取 `seq`。** 桥接端的 `seq` 每次位置上报都会递增，用它做歌词缓存键会让时间轴每秒重建一次，换行状态被反复重置，表现为整字跳变。指纹必须只对 `lyric` 对象本身做哈希。

**帧间隔要在入口统一算。** 只在「同一行」分支里取 `nanoTime`，换行那一帧不记录时间戳，下一帧间隔被算成 0，平滑推进失效。

**外推必须限幅且单调。** 轮询滞后时外推会无界前冲，位置越过整行后 `indexAt` 停在末行并判定已唱完，整行恒亮。同时要保证同一次播放中位置不倒退，否则轮询抖动会让高亮闪烁；跨行、seek、换曲这类大跨度回退必须放行。

**上报周期不等于轮询等待。** 外推余量若小于上报周期，高亮走完余量就停住等下一条上报。余量必须按实测周期自适应，上限要随本地时间一起推进，不能写成 `reportedMs + lead` 这种固定上限。

## 字内渐变

**裁剪有量化下限。** 裁剪边界只能落在整数像素上，一个汉字在 9px 字号下只有 9 像素宽，染色前沿最多只有 9 个可停留位置。这条限制无法靠增加条带数量或调羽化宽度绕过。

**改用逐顶点配色。** 字形是四边形，`VertexConsumer.setColor` 逐顶点调用，颜色是浮点量。给左两顶点已唱色、右两顶点未唱色，GPU 逐像素插值，前沿可以落在字内任意亚像素位置。一个字只画一次，不需要条带，也不需要为分色开裁剪。

实现分三层：

| 层 | 职责 |
| --- | --- |
| `GradientColorizer`（common，纯计算） | 决定每个字的左右端点色：完全在前沿左边取已唱色，完全在右边取未唱色，跨越前沿则左已唱右未唱 |
| `GradientGlyphWriter`（平台层） | 按原版几何写四个顶点 |
| `GlyphColors` | 跨层值对象，让 common 层不必知道 Minecraft 类型 |

**几何必须与 `BakedGlyph.render` 一致**，包括斜体补偿 `x0 += 1 - 0.25 * up`，否则斜体字的染色区会横向错位。UV 与位置的对应顺序也不能变。

**阴影要自己画。** 原版先用阴影色画一遍、再用主色在 `x - 1` 处画一遍，阴影色是原色 RGB 乘 0.25、alpha 不变。自写顶点时必须复刻这个顺序与偏移。

**用 `VarHandle` 而不是 Mixin。** 需要的只有 `u0 u1 v0 v1 left right up down` 八个私有字段。`VarHandle` 只依赖字段名，字段改名时 `available()` 转为 false，自动退回原版单色绘制——功能降级但不崩溃。

**1.21.1 与 26.1.2 的 API 不同。** 1.21.1 的 `BakedGlyph` 是普通类，`render` 把颜色当标量接收，UV 是私有字段。26.1.2 引入 `RenderPipeline` 与 `TextRenderable`，顶点级着色是公开能力，不需要反射。26.1.2 的移植方案见 [进度与待办](ROADMAP.md)。

### 横向滚动

横排未开启折行时，长行随演唱进度滚动。滚动规则取自 `ScrollStepper`：演唱点越过视口中线才推动文本，推动量恰为超出中线的距离，并夹在 `[-(行宽-视口宽), 0]`。演唱中的字始终停在中线附近。

滚动时所有裁剪区都必须再夹一次视口，否则已唱段会画出面板。

## 强调动画

够长的词组被唱到时整体上浮、向两侧展开并提亮，行末那一组幅度更大。参数移植自 AMLL：组时长至少 1 秒才参与，CJK 不限字数，非 CJK 限 2 到 7 字；幅度按组时长推导，有上限。

**缓动是脉冲形**：0 起、中点达峰、终点归零。动画结束强调完全消失，不是「渐入后保持」。单元测试包含中点峰值与终点归零两条锚。

**发光用提亮，不用光晕。** 原版字体是位图图集，字形按整像素对齐取样，任何位移或缩放都会让笔画按非整数倍采样。四向偏移叠成光晕在 9px 上等于四份错位副本互相覆盖。这里只改颜色：沿 RGB 向白色插值、保留 alpha，像素不动。

**不做缩放。** AMLL 的 1.1 倍放大在 Compose 的矢量字体上可行，在这里会让整个字重新采样。这条有专门的测试守住。

**CJK 双上限。** 中文按单字成词，因此连续汉字的强调组最多 5 字、动画最长 2.4 秒。

## 时间轴修补

**行末闭合。** 字级时间经常不完整。残缺在行中间看不出来，但行末没有下一个字接住填充，推算会跑出数组边界、把整行报成已唱。修补在时间轴构造时一次性做完（`LyricTimingFix`），不在渲染层逐帧判断。

规则：让一连串 `end == start` 的字按顺序均分到「该段结束」为止，界由后一个开始更晚的字或行末决定。行末本身不晚于该段起点时，退用下一行的开始，**上限 4 秒**——超过就交还给间奏提示。

**重叠的两行都显示。** 主唱未唱完、伴唱已进来是正常现象。只按开始时间取一行会让另一句连词带译文一起消失。`LyricTimeline.activeLinesAt` 用前缀最大结束时间把向前扫描限制在常数步内。

**没有引入外部解析器。** `LyricWord` 目前全部来自桥接插件，数据源单一。接入本地 LRC 或在线歌词源时才需要处理格式识别、不规则小数时间戳（`.1` 是 100ms 不是 1ms）、译文就近匹配。

## 配置界面

**所有改动即时生效**，没有「应用」按钮：渲染器每帧直接读 `LyricStyleConfig`。

**预览框**在界面顶端，走真实渲染路径而不是另画一份示意。颜色、字号、宽度、过渡的改动立刻可见。

**继承原版 `OptionsSubScreen`**（继承 `Screen`，再叠一层 `HeaderAndFooterLayout`）。滚动、标题、页脚、控件对齐、键盘导航与朗读全部由原版接管，自己只需要写 `addOptions()` 与预览那一行。两端使用**同一份界面代码**，`verifyMirroredRender` 守着不许分叉。

**预览占列表里的若干行。** `OptionsList` 的行高由 `Entry.render` 写死 20 像素，无法给单个控件更高空间。因此塞一个隐藏占位控件连续占住 N 行，再在自己的 `render` 里按这段实际坐标画预览。占几行由 `LyricGeometry.previewHeight` 按当前行数与行距实时算出。

**绘制顺序。** 调色与位置调整界面继承 `Screen` 且由自己控制绘制顺序，**不调 `super.render`**。`Screen.render` 一进来先调 `renderBackground` 再遍历控件，先自绘内容再调 `super.render` 会让背景遮罩压在最上层——整个界面发暗，只有按钮亮着。正确顺序：先 `renderBackground`，再自绘内容，最后逐个画控件。

**覆盖 `renderBackground`。** 1.20.5 起所有 Screen 默认给整屏叠一层高斯模糊，画在界面里的东西包括预览框里的歌词都会被糊掉。歌词预览要看清像素级细节，模糊让它失去意义。配置页继承 `OptionsSubScreen` 后同样要覆盖。

**预览用 `setPreviewArea(Bounds)` 实现**：渲染器按该矩形重新居中，并忽略用户偏移。预览中不滚动，超长直接截断。退出界面时必须清除预览区，否则下一次 HUD 绘制会把歌词画进那个框里。

**时间偏移只作用在「查时间轴」这一步**，不动外推时钟。在查表处加常量相当于整体平移时间轴，语义干净且可逆。

**数据源开关与连接状态分开。** 禁用只让 `isAlive()` 返回 false 从而停止出画，后台轮询继续跑，重新启用立刻有数据。开关状态单独持久化，重启后保持禁用。

### 颜色选择器

颜色页提供歌词预览、颜色调整目标与 `#AARRGGBB` 颜色编码输入框。

取色盘是**方形 SV 平面加独立色相条**：横轴饱和度、纵轴明度（上明下暗），色相由色相条决定。相比圆盘，明度是独立的一维，想调暗纵向拉到底即可。

方盘**不建纹理**，用两层 `fillGradient` 叠加等效：底层左白右纯色（饱和度），上层上透明下黑（明度）。色相一变只换一个颜色参数，不必重算 128x128 整块像素。

几何放在 `ColorSquare`（纯计算，可单测），界面只负责画渐变与响应鼠标。`HsvColor` 负责 HSV 与 ARGB 互转，往返不漂移。

## 位置调整

`/linklyric location` 打开一个**全透明界面**，此时光标可见。配置页里的「调整位置…」也走这里，两者是同一个界面。

**语义是先拖、后确认。** 按住歌词拖动只改屏幕上的位置，松手既不落盘也不退出；点「保存」（或回车）才写盘并关闭，点「取消」（或 Esc）回到进入时的位置。未保存时顶部提示「位置已改动，尚未保存」。

这条语义要求拖动结束时**不能**顺手落盘：控制器的 `end()` 只停止跟随，`commit()` 才写盘，`revert()` 回滚到会话起点。保存后再进入调整，回滚基线更新到新位置。

**必须开界面。** HUD 状态下光标被游戏锁在窗口中心，玩家既看不见指针也无法按住拖动。界面本身不画背景，只叠一层歌词与拖动底板，下方游戏画面保持可见，单人游戏也不暂停。

**冷启动自动打开。** 关闭状态下执行 `location` 会自动打开歌词：用户正是在靠它调位置。

**位置存成相对屏幕中心的偏移**，不是绝对坐标。换分辨率、改 GUI 缩放之后歌词仍停在画面相同的相对位置。默认值 `(0, 0)` 等价于底部居中。

### 命中与拖动

**按下点必须落在歌词包围盒内**才算开始拖动。空白处按下不拖，界面把这次操作当作放弃并关闭。

**包围盒是渲染的副作用。** `FloatingLyricRenderer.bounds()` 返回歌词最近一帧的屏幕包围盒，范围取决于字体宽度与滚动偏移，只有真正画过一次才知道。每帧开头统一清空、由出画路径写入；没有出画时为空，空包围盒不命中任何点。

**用累计位移而非帧间增量。** 界面用 `mouseDragged` 给出的当前光标位置计算，而不是 `dragX/dragY`：掉帧时增量会丢。

**Fabric 没有鼠标移动事件。** `ScreenMouseEvents` 只有 click/release/scroll。拖动位置由 `ClientTickEvents` 按 tick 轮询光标，20Hz 足够跟手；确认与取消仍走 Screen 事件，拖动期间能吞掉点击避免误触界面按钮。

**光标坐标必须用 `getGuiScale()` 换算**成 GUI 坐标。直接用窗口像素会让高 DPI 下的位移被放大数倍。

**首帧只定基准点。** 指令入口拿不到「按在歌词上」这个前提，首帧不移动，否则一执行指令歌词就瞬移到光标处。

## 性能与测试

**轮询。** 在独立线程执行，每次请求结束后等待 200ms。`pollSnapshot()` 只读缓存，绝不发网络请求。连续失败 6 次才判定断连，成功响应重置计数。连接 / 读取超时分别为 500ms / 800ms。

**缓存清理。** 判定断连或调用 `stop()` 都会清空快照、歌词、能力、本地指纹与 ETag。

**条件请求。** `lyricOmitted: true` 仅在已有 ETag 且响应 ETag 缺失或一致时接受，且不能同时携带 `lyric`；否则按失败处理。

**不构造 `Component`。** 中文歌词每帧重建会产生大量短命对象。
